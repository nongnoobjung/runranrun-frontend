# ก้าว · เว็บ (runranrun-frontend)

เว็บสมัครงานวิ่งตามดีไซน์แบบ D (CI ฟ้า-ขาว) คู่กับ API ที่ [runranrun-api](https://github.com/nongnoobjung/runranrun-api)

- Next.js 16.4 (App Router, Cache Components, Partial Prefetching) + React 19
- Tailwind CSS v4: สี ฟอนต์ และมุมโค้งของแบรนด์อยู่ใน `@theme` ที่ `src/app/globals.css` จุดเดียว
- ฟอนต์ Prompt (ไทย + ละติน) ผ่าน `next/font`
- หน้านักวิ่งมีสองภาษา: ไทยที่ URL ปกติ (`/events`) อังกฤษที่ `/en/...` (`/en/events`) สลับได้จากปุ่ม EN / ไทย บน header · backoffice ผู้จัดงานและแอดมินเป็นภาษาไทยอย่างเดียว

## เริ่มใช้งาน

ต้องรัน API ก่อน (ดู README ของ runranrun-api: `docker compose up -d`, `pnpm db:migrate`, `pnpm db:seed`, `pnpm dev:api`)

```bash
cp .env.example .env.local     # API_URL=http://localhost:4000
pnpm install
pnpm dev                       # http://localhost:3000
```

## หน้าที่ทำแล้ว

ทุกหน้าในตารางนี้มีฉบับภาษาอังกฤษที่ `/en` + เส้นทางเดิม เช่น `/en/events/[slug]`

| หน้า | เส้นทาง |
|---|---|
| หน้าแรก: งานที่เปิดรับสมัคร | `/` |
| หางานวิ่ง: ค้นหาชื่องาน/สถานที่, จังหวัด, เดือน, ประเภท, ช่วงระยะ, เฉพาะที่เปิดรับสมัคร (ตัวกรองอยู่ใน URL แชร์ลิงก์ได้) | `/events` |
| รายละเอียดงาน: รูปปก, เกี่ยวกับงาน (Markdown พร้อมรูป), แกลเลอรี (เลื่อนข้างบนมือถือ เปิดดูเต็มจอ), แผนที่เส้นทาง, กติกา, คำถามที่พบบ่อย + เลือกระยะและจำนวนผู้วิ่ง · ที่ `/en/events/[slug]` แสดงข้อความภาษาอังกฤษของผู้จัด (ช่องที่ว่างใช้ไทย) | `/events/[slug]` |
| เข้าสู่ระบบ (ชั่วคราว: อีเมล) | `/login` |
| กรอกข้อมูลผู้วิ่ง ไซซ์เสื้อ ผู้ชำระเงิน โค้ดส่วนลด และขอใบกำกับภาษีเต็มรูป (ไม่บังคับ) | `/checkout/[id]` |
| สรุปยอดและชำระเงิน PromptPay (QR + เช็กสถานะทุก 3 วินาที) | `/orders/[id]/pay` |
| ชำระสำเร็จ พร้อมเลขบิบ และลิงก์ใบเสร็จ | `/orders/[id]/success` |
| ใบเสร็จ / ใบกำกับภาษีที่พิมพ์ลง A4 ได้ (หรือบันทึกเป็น PDF จากเบราว์เซอร์), เครื่องหมายคืนเงิน, ขอใบกำกับภาษีเต็มรูปภายหลัง (ชื่อ, เลขผู้เสียภาษี 13 หลัก, สำนักงานใหญ่/สาขา/บุคคลธรรมดา, ที่อยู่) · ลิงก์จากหน้าชำระสำเร็จ บัตรวิ่ง และอีเมลยืนยัน | `/orders/[id]/receipt` |
| งานของฉัน | `/me/events` |
| บัตรวิ่ง + QR รับเสื้อ | `/me/registrations/[id]` |
| ขอยกเลิกและคืนเงินตามนโยบายของงาน (กรอกบัญชีรับเงินคืนเมื่อจ่ายด้วย PromptPay) | `/me/registrations/[id]/refund` |
| ผลการแข่งขัน: แยกระยะ, ค้นหาชื่อหรือบิบ, กรองเพศ (เปิดเมื่อผู้จัดเผยแพร่) | `/events/[slug]/results` |
| ผลการแข่งขันรวมทุกงาน: การ์ดงานที่ประกาศผลแล้ว, ค้นหาตัวเองข้ามงานด้วยชื่อหรือบิบ, ผลของฉันเมื่อเข้าสู่ระบบ (เมนู "ผลการแข่งขัน") | `/results` |
| คิวเข้าสมัคร (waiting room): งานที่ผู้จัดเปิดคิว หน้างานให้กดเข้าคิวแทนการเลือกระยะ แสดงลำดับ จำนวนคนก่อนหน้า เวลารอโดยประมาณ และแถบความคืบหน้า อัปเดตเองผ่าน server action ถึงคิวแล้วพากลับไปเลือกระยะพร้อมเวลาที่เหลือ | `/events/[slug]/queue` |
| คิว waitlist: ลำดับคิว, ถึงคิวแล้วนับถอยหลังและกดสมัคร, ออกจากคิว (เข้าคิวจากปุ่มของระยะที่เต็มในหน้างาน) | `/me/waitlist` |
| โอนสิทธิ์ให้คนอื่นด้วยอีเมล, ดูสถานะ, ยกเลิกการโอน | `/me/registrations/[id]/transfer` |
| เปลี่ยนระยะ: เลือกระยะ ดูส่วนต่างและค่าธรรมเนียม แล้วชำระหรือเปลี่ยนทันที | `/me/registrations/[id]/race-change` |
| ข้อมูลผู้วิ่งที่บันทึกไว้: เพิ่ม แก้ ลบ ตั้งเป็นตัวฉัน · ตอนสมัครและรับโอนเลือกได้เลย (ตัวฉันเลือกให้อัตโนมัติ) หรือติ๊กบันทึกคนที่กรอกใหม่ เลขบัตรไม่ถูกส่งมาที่เบราว์เซอร์ | `/me/profiles` |
| ความเป็นส่วนตัวและข้อมูลของฉัน (PDPA): ความยินยอมและประวัติ, เปิด/ปิดรับข่าวสาร, ดาวน์โหลดข้อมูลเป็น JSON, ปิดบัญชี | `/me/privacy` |
| นโยบายความเป็นส่วนตัว, เงื่อนไขการใช้งาน, นโยบายคืนเงิน (ลิงก์จาก footer) | `/privacy`, `/terms`, `/refund-policy` |
| สิทธิ์ที่มีคนโอนให้ (และที่โอนให้คนอื่น) · รับสิทธิ์โดยกรอกข้อมูลผู้วิ่งของตัวเอง | `/me/transfers`, `/me/transfers/[id]` |

## Backoffice แอดมิน (`/admin`)

เข้าสู่ระบบด้วย `admin@kao.example` (superadmin จาก `pnpm db:seed` ของ API) แล้วเปิด `/admin` คนที่ไม่มีบทบาทแพลตฟอร์มจะเห็นหน้า 404

| หน้า | เส้นทาง |
|---|---|
| ภาพรวม: งานรอตรวจ, ผู้จัดรอ KYC, ยอดรอสร้างรอบจ่าย, รอบที่ยังไม่โอน | `/admin` |
| ตรวจงาน: คิวงานที่ผู้จัดกดเปิดครั้งแรก · ดูข้อมูล ระยะ ราคา ความพร้อม แล้วอนุมัติ (เปิดทันที) หรือส่งกลับพร้อมข้อความ | `/admin/reviews`, `/admin/reviews/[eventId]` |
| ผู้จัดงาน: แยกตามสถานะ · ข้อมูลนิติบุคคล เอกสาร ทีมงาน งาน · เปิดไฟล์เอกสาร KYC, ให้ผ่านหรือส่งกลับทีละไฟล์พร้อมเหตุผล, ยืนยันบัญชีรับเงินที่ผู้จัดส่งมา (เห็นเลขเต็มเพื่อเทียบกับสมุดบัญชี) · อนุมัติ KYC, ระงับ/คืนสิทธิ์, ตั้งให้รอตรวจหรือเปิดเองได้, บันทึกบัญชีรับเงินที่ตรวจแล้ว | `/admin/organizations`, `/admin/organizations/[orgId]` |
| จ่ายเงินผู้จัด (finance ขึ้นไป): งานที่มียอดค้าง → สร้างรอบ → อนุมัติ → บันทึกเลขอ้างอิงการโอน หรือยกเลิกรอบ | `/admin/payouts` |
| ค่าธรรมเนียมแพลตฟอร์ม (finance ขึ้นไป): อัตรา default (% ของยอดขาย + บาทต่อผู้วิ่ง, มีผลทันทีหรือตั้งวันเริ่ม) พร้อมประวัติ และผู้จัดที่มีอัตราของตัวเอง · หน้าผู้จัดแสดงอัตราที่คำสั่งซื้อใหม่ใช้ ตั้งอัตราเฉพาะทีม หรือกลับไปใช้ default | `/admin/fees`, `/admin/organizations/[orgId]` |
| ผู้ใช้: ค้นหาด้วยอีเมลหรือชื่อ กรองสถานะ/ทีมงาน · สิทธิ์วิ่ง คำสั่งซื้อ ทีมผู้จัด สิทธิ์ เข้าระบบล่าสุด · ระงับพร้อมเหตุผล (ออกจากระบบทันที) / ยกเลิกการระงับ (admin ขึ้นไป, บัญชีทีมงานต้อง superadmin) · เปลี่ยนสิทธิ์แพลตฟอร์ม (superadmin) · แก้บัญชีตัวเองไม่ได้ | `/admin/users`, `/admin/users/[userId]` |
| บันทึกการทำงาน (ทุกบทบาท): กรองผู้จัด อีเมลผู้ทำ การกระทำ (ขึ้นต้นด้วย) ช่วงวันที่ ทีละ 50 รายการ · ข้อมูลก่อน/หลังเป็น JSON (API ซ่อนข้อมูลลับและเลขเต็มแล้ว) · หน้าผู้จัด ตรวจงาน และผู้ใช้มีลิงก์ไปบันทึกที่กรองไว้ | `/admin/audit`, `/admin/audit/[id]` |

- ผู้จัดเห็นสถานะ "รอตรวจ" และข้อความที่ถูกส่งกลับในหน้าข้อมูลงาน และเห็นรอบที่โอนแล้วในหน้าการเงิน

| เสื้อและไซซ์ (สต็อก) | `.../shirts` |
| คูปอง | `.../coupons` |
| ผู้สมัคร: ค้นหา, กรอง, รายละเอียด, ดูเลขบัตร (บันทึกการเข้าถึง), Export CSV | `.../registrations` |

| โอนสิทธิ์และเปลี่ยนระยะ: รายการทั้งหมดของงาน · ตั้งค่าธรรมเนียมและกำหนดที่ข้อมูลงาน · ย้ายระยะให้นักวิ่งที่รายละเอียดผู้สมัคร | `.../changes` |
| คิวเข้าสมัคร: เปิด/ปิด waiting room และจำนวนคนที่ปล่อยเข้าสมัครต่อนาที ในหน้าข้อมูลงาน | `.../edit` |
| Waitlist: คิวแต่ละระยะ, สถานะข้อเสนอ, เสนอที่ว่างให้คิวทันที · เปิดคิวได้ที่ข้อมูลงาน | `.../waitlist` |
| ทีมงาน: เชิญด้วยอีเมล, เปลี่ยนบทบาท, นำออก, ตารางสิทธิ์ของแต่ละบทบาท (ใช้กับทุกงานในองค์กร) | `.../team` |

- **ตามบทบาท:** owner และ admin แก้ได้ทุกอย่าง, staff ใช้หน้ารับของ, finance และ viewer ดูอย่างเดียว
  - ปุ่มที่ทำไม่ได้จะซ่อนไว้ และ API ก็ตรวจซ้ำอีกชั้น
  - เฉพาะ owner ที่จัดการทีมงานได้ คนที่ถูกเชิญเข้าทีมเองเมื่อเข้าสู่ระบบด้วยอีเมลนั้น (ยังไม่มีอีเมลเชิญ)
- **วันเวลา:** ทุกช่องที่ผู้จัดกรอกเป็นเวลากรุงเทพฯ
- **ราคา:** กรอกเป็นบาท ส่งไป API เป็นสตางค์
- **คำถามเพิ่มเติม:** ฟอร์มสมัครของนักวิ่งแสดงคำถามของระยะที่สมัคร API เป็นคนตรวจคำตอบ แล้วเว็บแสดงข้อผิดพลาดใต้คำถามนั้น คำตอบดูได้ในรายละเอียดผู้สมัครและ CSV
- **รับของแบบออฟไลน์:** หน้า `.../checkin` ดาวน์โหลดรายชื่อผู้สมัครที่ชำระแล้ว (ไม่มีเบอร์ อีเมล เลขบัตร QR เก็บเป็น hash) ไว้ใน IndexedDB ทุกครั้งที่เปิดหน้าและหลังส่งคิว
  - เน็ตหลุด (`offline` ของเบราว์เซอร์ หรือเรียก server ไม่สำเร็จ) ค้นจากรายชื่อในเครื่อง การมอบของเก็บเป็นคิวพร้อม `clientUuid` เวลาที่มอบ และชื่อผู้รับแทน คิวอยู่รอดแม้รีโหลดหรือปิดเครื่อง
  - กลับมาออนไลน์ ส่งคิวเองตามลำดับผ่าน server action (`POST .../checkins/batch` ทีละไม่เกิน 200) ลองใหม่ทุก 30 วินาทีถ้ายังส่งไม่ได้ หรือกด "ส่งตอนนี้" ส่งซ้ำได้ไม่บันทึกซ้ำ
  - รายการที่ระบบไม่รับ (รับไปแล้วที่จุดอื่น มีคำขอคืนเงิน ยังไม่ชำระ) ขึ้นในกล่อง "ส่งไม่สำเร็จ" ทีละรายการจนกด "รับทราบ"
  - ใน production มี service worker (`public/checkin-sw.js`, scope `/organizer/`) เก็บหน้ารับของและไฟล์ `/_next/static` ไว้ เครื่องที่เคยเปิดหน้านี้ตอนออนไลน์จึงเปิดใหม่ได้แม้ไม่มีเน็ต
- **PDPA:** ฟอร์มสมัครและฟอร์มรับโอนต้องติ๊กยอมรับเงื่อนไข นโยบายความเป็นส่วนตัว และการส่งข้อมูลให้ผู้จัดก่อนส่ง ส่วนรับข่าวสารไม่บังคับและไม่ติ๊กไว้ก่อน เว็บใช้แค่คุกกี้ที่จำเป็นจึงไม่มีแบนเนอร์คุกกี้
  - ข้อมูลบริษัทในหน้านโยบาย (`src/lib/legal.ts`) ยังเป็นค่าในวงเล็บ ต้องใส่ข้อมูลจริงและให้ทนายตรวจก่อนเปิดใช้งาน `POLICY_VERSION` ต้องตรงกับของ API
- **Export CSV:** วิ่งผ่าน route ของเว็บที่แนบ token จาก cookie ให้ เบราว์เซอร์จึงไม่ได้ถือ token ของ API
- **เอกสาร KYC:** อัปโหลดผ่าน server action (`serverActions.bodySizeLimit` 11 MB) แล้วส่งต่อเป็น multipart ไฟล์เปิดผ่าน route ของเว็บ (`src/lib/file-proxy.ts`) ไม่มีลิงก์ตรงไปที่ไฟล์ และไม่ให้เบราว์เซอร์ cache
- **เนื้อหาและรูปของงาน:** ข้อความของผู้จัดมาเป็น `{ th, en }` ใช้ `pick()` ใน `src/lib/content.ts` เลือกตามภาษาของหน้า (`getLocale()` / `useLocale()`, ภาษาอังกฤษว่างก็ใช้ไทย) ข้อความของหน้าอยู่ในพจนานุกรม `src/i18n/dict/events.ts`
  - รายละเอียดและกติกาเป็น Markdown แสดงด้วย `<Markdown>` (`src/components/markdown.tsx`, react-markdown): หัวข้อ ตัวหนา ตัวเอียง รายการ ลิงก์ quote รูป ไม่แสดง HTML ดิบเลย ลิงก์ภายนอกเปิดแท็บใหม่ `rel="noopener noreferrer nofollow ugc"` ลิงก์ `javascript:` ถูกตัด รูปรับเฉพาะ `/media/` และ https
  - รูปอัปโหลดผ่าน server action แล้ว API ย่อเป็น WebP เว็บเสิร์ฟรูปที่ `/media/event-images/[file]` (route ส่งต่อจาก API `/v1/media` พร้อม cache 1 ปี) เส้นทางนี้ใส่ใน Markdown ได้ตรง ๆ

## โครงสร้าง

- **เบราว์เซอร์ไม่เรียก API ตรง:** server component และ server action (`src/app/actions.ts`) เรียก API ผ่าน `src/lib/api.ts`
- **JWT อยู่ใน httpOnly cookie:** JavaScript ฝั่งเบราว์เซอร์อ่านไม่ได้
- **ข้อมูลที่ขึ้นกับคำขอ:** ทุกหน้าที่อ่าน cookie หรือ params อยู่ใน `<Suspense>` ตามกติกา Cache Components หน้าเปล่าจึงแสดงทันที แล้วข้อมูลค่อยตามมา
- **คำสั่งซื้อไม่ซ้ำ:** ฟอร์มสมัครส่ง `Idempotency-Key` ที่คำนวณจากข้อมูลในฟอร์ม กดซ้ำหรือเน็ตหลุดแล้วส่งใหม่จะไม่สร้างคำสั่งซื้อซ้ำ
- **หน้านักวิ่งกับ backoffice แยก layout:** หน้านักวิ่งอยู่ใน `src/app/[lang]/(site)` ที่มี header/footer ส่วน `/organizer` และ `/admin` มี root layout ภาษาไทยของตัวเอง
- **สองภาษา (ไทย / อังกฤษ):**
  - `src/proxy.ts` rewrite URL ปกติไปที่ `app/[lang]` ด้วย `lang=th` ส่วน `/en/...` ใช้ `lang=en` ตรง ๆ · ลิงก์สลับภาษาไปที่ `/en/...` หรือ `/th/...` (proxy จำภาษาไว้ใน cookie `kao_locale` แล้ว redirect `/th/...` กลับเป็น URL ปกติ) คนที่เลือกอังกฤษไว้แล้วเปิด URL ปกติจะถูกส่งไป `/en/...` · ทุกหน้ามี header `Link` บอก hreflang ของอีกภาษา
  - ภาษามาจาก URL ไม่ใช่ cookie หน้าจึงยัง prerender เป็น static shell แยกตามภาษาได้ตามกติกา Cache Components และ `<html lang>` ถูกต้องตั้งแต่ HTML แรก
  - Server Component: `getLocale()` / `getT()` จาก `@/i18n/server` (อ่านจาก `next/root-params`) · Client Component: `useLocale()` / `useT()` / `useLocalePath()` จาก `@/i18n/client` · Server Action: `actionLocale()` (proxy ใส่ header ให้)
  - ข้อความอยู่ใน `src/i18n/dict/<ส่วน>.ts` เขียนผ่าน `defineDict({ th, en })` ไทยเป็นต้นฉบับ อังกฤษต้องมี key และชนิดตรงกันทุกตัว ขาดหรือเกินแม้ key เดียว `pnpm typecheck` จะไม่ผ่าน
  - ลิงก์ในหน้านักวิ่งใช้ `Link` จาก `@/i18n/link` (ESLint ห้าม `next/link` ในหน้านักวิ่ง) redirect ใช้ `localePath(locale, path)` · `?next=` เก็บเป็น path ไม่มีภาษา
  - ข้อความที่ผู้จัดเขียน (ชื่องาน ฯลฯ) ใช้ `localized(locale, event.name)`: มีภาษาอังกฤษก็แสดง ไม่มีก็ใช้ภาษาไทย
  - หน้ากฎหมาย (`/privacy`, `/terms`, `/refund-policy`) เก็บเนื้อหาไทยและอังกฤษไว้คู่กันในไฟล์หน้า (`Record<Locale, …>` ขาดภาษาไหน typecheck ไม่ผ่าน) ฉบับอังกฤษบอกว่าถ้าต่างกันให้ถือฉบับไทย ชื่อบริษัทที่ยังเป็น placeholder มีทั้งสองภาษาใน `src/lib/legal.ts`
  - วันที่/เวลา/ตัวเลขใช้ `fmtFor(locale)` (ไทยปี ค.ศ. แบบเดิม อังกฤษแบบ `14 Feb 2027`) ราคาเป็น `฿` ทั้งสองภาษา ข้อความ error จาก API แปลด้วย `problemMessage(problem, locale)`
- **ไซซ์เสื้อ:** กดสมัครแล้วจองที่ทันที ไซซ์เสื้อจองตอนส่งฟอร์มผ่าน `PUT /v1/checkout/sessions/:id/variants` ถ้าไซซ์หมดจะเตือนก่อนสร้างคำสั่งซื้อ
- **Waiting room:** token ที่ได้ตอนถึงคิวเก็บใน httpOnly cookie ต่องาน (`kao_queue_<eventId>`) แล้ว `startCheckout` ส่งให้ API ใน `X-Queue-Admission` หมดอายุหรือไม่มีจะพากลับหน้าคิว
- **Rate limit:** API ตอบ 429 `RATE_LIMITED` เว็บแสดงข้อความตามภาษาของหน้าพร้อมเวลาที่ต้องรอ ตั้ง `WEB_PROXY_SECRET` ให้ตรงกับ API เพื่อส่ง IP ของผู้ใช้ไปด้วย (ไม่ตั้ง ทุกคนนับเป็น IP ของ web server)
- **ใบเสร็จ:** API ออกเอกสารตอนชำระเงิน เว็บแค่แสดง ป้ายกำกับตามภาษาของหน้า (`src/i18n/dict/receipts.ts`) จำนวนเงินทศนิยมสองตำแหน่ง ตอนพิมพ์ header/footer ของเว็บ ปุ่ม และฟอร์มซ่อนด้วย `print:hidden` และ `@page` A4 ใน `globals.css` เลขผู้เสียภาษีตรวจ checksum ในเว็บก่อนส่ง (`src/lib/billing.ts`) แล้ว API ตรวจซ้ำ
- **ภาษาของอีเมล:** ตอนเข้าสู่ระบบและตอนสมัคร server action บอก API ด้วย `PUT /v1/me/locale` อีเมลอัตโนมัติ (ชำระเงิน บิบ คืนเงิน โอนสิทธิ์ ผลการแข่งขัน ฯลฯ) จึงมาเป็นภาษาที่นักวิ่งใช้ล่าสุด
- **ปุ่มจำลองการจ่าย:** `ENABLE_DEV_TOOLS=true` เปิดปุ่ม "จำลองว่าจ่ายแล้ว" ห้ามเปิดใน production
