# ก้าว · เว็บ (runranrun-frontend)

เว็บสมัครงานวิ่งตามดีไซน์แบบ D (CI ฟ้า-ขาว) คู่กับ API ที่ [runranrun-api](https://github.com/nongnoobjung/runranrun-api)

- Next.js 16.4 (App Router, Cache Components, Partial Prefetching) + React 19
- Tailwind CSS v4: สี ฟอนต์ และมุมโค้งของแบรนด์อยู่ใน `@theme` ที่ `src/app/globals.css` จุดเดียว
- ฟอนต์ Prompt (ไทย + ละติน) ผ่าน `next/font`

## เริ่มใช้งาน

ต้องรัน API ก่อน (ดู README ของ runranrun-api: `docker compose up -d`, `pnpm db:migrate`, `pnpm db:seed`, `pnpm dev:api`)

```bash
cp .env.example .env.local     # API_URL=http://localhost:4000
pnpm install
pnpm dev                       # http://localhost:3000
```

เข้าสู่ระบบด้วย `admin@kao.example` (superadmin จาก `pnpm db:seed` ของ API) แล้วเปิด `/admin` คนที่ไม่มีบทบาทแพลตฟอร์มจะเห็นหน้า 404

| ทีมงาน: เชิญด้วยอีเมล, เปลี่ยนบทบาท, นำออก, ตารางสิทธิ์ของแต่ละบทบาท (ใช้กับทุกงานในองค์กร) | `.../team` |

- **ตามบทบาท:** owner และ admin แก้ได้ทุกอย่าง, staff ใช้หน้ารับของ, finance และ viewer ดูอย่างเดียว

  - เฉพาะ owner ที่จัดการทีมงานได้ คนที่ถูกเชิญเข้าทีมเองเมื่อเข้าสู่ระบบด้วยอีเมลนั้น (ยังไม่มีอีเมลเชิญ)
- **วันเวลา:** ทุกช่องที่ผู้จัดกรอกเป็นเวลากรุงเทพฯ
- **ราคา:** กรอกเป็นบาท ส่งไป API เป็นสตางค์
- **คำถามเพิ่มเติม:** ฟอร์มสมัครของนักวิ่งแสดงคำถามของระยะที่สมัคร API เป็นคนตรวจคำตอบ แล้วเว็บแสดงข้อผิดพลาดใต้คำถามนั้น คำตอบดูได้ในรายละเอียดผู้สมัครและ CSV
- **รับของแบบออฟไลน์:** หน้า `.../checkin` ดาวน์โหลดรายชื่อผู้สมัครที่ชำระแล้ว (ไม่มีเบอร์ อีเมล เลขบัตร QR เก็บเป็น hash) ไว้ใน IndexedDB ทุกครั้งที่เปิดหน้าและหลังส่งคิว
  - เน็ตหลุด (`offline` ของเบราว์เซอร์ หรือเรียก server ไม่สำเร็จ) ค้นจากรายชื่อในเครื่อง การมอบของเก็บเป็นคิวพร้อม `clientUuid` เวลาที่มอบ และชื่อผู้รับแทน คิวอยู่รอดแม้รีโหลดหรือปิดเครื่อง
  - กลับมาออนไลน์ ส่งคิวเองตามลำดับผ่าน server action (`POST .../checkins/batch` ทีละไม่เกิน 200) ลองใหม่ทุก 30 วินาทีถ้ายังส่งไม่ได้ หรือกด "ส่งตอนนี้" ส่งซ้ำได้ไม่บันทึกซ้ำ
  - รายการที่ระบบไม่รับ (รับไปแล้วที่จุดอื่น มีคำขอคืนเงิน ยังไม่ชำระ) ขึ้นในกล่อง "ส่งไม่สำเร็จ" ทีละรายการจนกด "รับทราบ"
  - ใน production มี service worker (`public/checkin-sw.js`, scope `/organizer/`) เก็บหน้ารับของและไฟล์ `/_next/static` ไว้ เครื่องที่เคยเปิดหน้านี้ตอนออนไลน์จึงเปิดใหม่ได้แม้ไม่มีเน็ต
- **Export CSV:** วิ่งผ่าน route ของเว็บที่แนบ token จาก cookie ให้ เบราว์เซอร์จึงไม่ได้ถือ token ของ API

## โครงสร้าง

- **เบราว์เซอร์ไม่เรียก API ตรง:** server component และ server action (`src/app/actions.ts`) เรียก API ผ่าน `src/lib/api.ts`
- **JWT อยู่ใน httpOnly cookie:** JavaScript ฝั่งเบราว์เซอร์อ่านไม่ได้
- **ข้อมูลที่ขึ้นกับคำขอ:** ทุกหน้าที่อ่าน cookie หรือ params อยู่ใน `<Suspense>` ตามกติกา Cache Components หน้าเปล่าจึงแสดงทันที แล้วข้อมูลค่อยตามมา
- **คำสั่งซื้อไม่ซ้ำ:** ฟอร์มสมัครส่ง `Idempotency-Key` ที่คำนวณจากข้อมูลในฟอร์ม กดซ้ำหรือเน็ตหลุดแล้วส่งใหม่จะไม่สร้างคำสั่งซื้อซ้ำ
- **หน้านักวิ่งกับ backoffice แยก layout:** หน้านักวิ่งอยู่ใน route group `(site)` ที่มี header/footer ส่วน `/organizer` มีแถบเมนูของตัวเอง
- **ไซซ์เสื้อ:** กดสมัครแล้วจองที่ทันที ไซซ์เสื้อจองตอนส่งฟอร์มผ่าน `PUT /v1/checkout/sessions/:id/variants` ถ้าไซซ์หมดจะเตือนก่อนสร้างคำสั่งซื้อ
- **ปุ่มจำลองการจ่าย:** `ENABLE_DEV_TOOLS=true` เปิดปุ่ม "จำลองว่าจ่ายแล้ว" ห้ามเปิดใน production

## Test

```bash
pnpm typecheck && pnpm lint    # TypeScript + ESLint
pnpm test                      # unit test (vitest)
pnpm test:e2e                  # Playwright บน desktop และมือถือ: นักวิ่งสมัครจนได้บัตรวิ่ง, ผู้จัดสร้างงานจนเปิดรับสมัคร, ค้นหาผู้สมัครและมอบของหน้างาน, ปิดเน็ตแล้วมอบของจากรายชื่อในเครื่อง (รีโหลดตอนออฟไลน์ได้) กลับมาออนไลน์แล้วส่งคิวจนหน้าผู้สมัครขึ้นว่ารับแล้ว และแจ้งรายการที่จุดอื่นมอบไปก่อน, เชิญทีมงานจนเข้าทีมแล้วนำออก, ผู้จัดเพิ่มคำถามบังคับแล้วนักวิ่งต้องตอบ, ออกบิบเอง/ทั้งหมด/จาก CSV, นักวิ่งขอคืนเงินจนผู้จัดโอนคืน, ผู้จัดยกเลิกสิทธิ์พร้อมคืนบางส่วน, สรุปการเงินและ Export ธุรกรรม, นำเข้าและเผยแพร่ผลแล้วนักวิ่งค้นหาผลตัวเอง, เขียนข่าวแล้วส่งทดสอบ ส่งจริง และตั้งเวลา, นักวิ่งเข้าคิวระยะที่เต็มแล้วได้สิทธิ์สมัครเมื่อมีที่ว่าง, โอนสิทธิ์ให้เพื่อนที่กรอกข้อมูลเองแล้วได้บิบเดิม, เปลี่ยนไประยะที่ยาวกว่าแล้วจ่ายส่วนต่าง, ค้นหางานด้วยชื่อ ระยะ และจังหวัด, บันทึกข้อมูลตัวเองแล้วสมัครโดยไม่ต้องกรอกใหม่, แอดมินอนุมัติผู้จัดใหม่ ตรวจงานแรก (ส่งกลับแล้วอนุมัติ) และจ่ายเงินผู้จัด, คนทั่วไปเข้าหน้าแอดมินไม่ได้
```

`test:e2e` ต้องมี API รันอยู่ที่ `API_URL` (ใช้ `PAYMENT_GATEWAY=fake`, `ENABLE_DEV_ENDPOINTS=true` และ seed ข้อมูลแล้ว)

เว็บที่ทดสอบอยู่ที่ `WEB_URL` (ค่าเริ่มต้น `http://localhost:3000`) ถ้ามีเว็บรันอยู่ที่นั่นแล้ว Playwright จะใช้ตัวนั้น ถ้ายังไม่มีจะ build แล้ว start ที่ port ของ `WEB_URL` ให้เอง ถ้า port 3000 / 4000 ในเครื่องไม่ว่าง ให้ระบุทั้งสองค่า เช่น

```bash
WEB_URL=http://localhost:3100 API_URL=http://localhost:4100 pnpm test:e2e
```
